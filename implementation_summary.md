# Implementation Summary

## What I built

A Jupyter notebook (`llm_judge_evaluation.ipynb`) that evaluates a customer-service chatbot for NordHome, a fictional home-goods retailer, using the OpenAI API directly. The chatbot is gpt-4o-mini with NordHome's return policy and a short product catalogue as its system prompt. It answered the 5 test prompts designed in Step 3: a standard return, a used-mattress return (not allowed), a lamp question with a missing warranty fact, an angry complaint about a damaged sofa, and a safety incident with a legal threat. Each reply was then graded by an LLM judge (also gpt-4o-mini, temperature 0, JSON output) using the judge prompt from Step 4. The judge compares each reply against an expected correct answer and returns a 1–5 score, its reasoning, and true/false on three criteria: empathy/tone, policy accuracy, and no invented promises. The notebook records time, input/output tokens and cost per case, and saves everything to `evaluation_results.json`.

## Key findings

The chatbot averaged **4.2/5**. Four of five cases scored 5/5: it applied the return policy correctly (including refusing the used mattress), did not invent a warranty, and refused extra compensation to the angry sofa customer without becoming defensive. No case contained an invented promise (5/5 on that criterion). The one failure was the most serious case: **Case 5 (lamp burned a child, customer mentions a lawyer) scored 1/5**. The bot used the required escalation phrase but did not tell the customer to stop using the lamp and showed no concern for the injury. It followed the escalation rule mechanically and dropped the rest of the instruction. A rule-based check for the exact phrase alone would have marked this reply as a pass, which shows why the judge is needed alongside simple checks.

The judge itself showed a weakness: by its own scale, Case 5 (two criteria missed, nothing invented) should be a 2, but it gave a 1. It also gave no 4s at all, which may mean it is too lenient on the passing cases. With only 5 cases, one run, no calibration set, and the same model writing and grading the replies (self-preference risk), these results are directional only. Running the judge cost **$0.0011** for 5 cases (5,052 input + 589 output tokens, about 2.1 seconds per case), roughly $0.22 per 1,000 graded conversations at gpt-4o-mini prices. That cost excludes the 5 chatbot calls. Next steps: rewrite the escalation instruction so concern and "stop using" are required parts of the handover, add a calibration set of human-scored replies, and run each case several times to measure score variance.
