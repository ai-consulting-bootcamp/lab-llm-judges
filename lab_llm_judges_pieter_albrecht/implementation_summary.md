# Implementation Summary

## What I built
A Python evaluation pipeline (`llm_judge_evaluation.py`) using the OpenAI API directly. For each of the five test cases from `evaluation_design.md`, gpt-4o-mini generates a loan rejection letter from an applicant record. Each letter is then verified in two independent ways: (1) rule-based checks (required keywords such as the rejection reason and Kifid, regex checks for forbidden or fabricated terms, and a simple Dutch-language check), and (2) an LLM-as-judge (gpt-4o-mini, temperature 0, JSON mode) using the judge prompt from Step 4, run three times per case. The script records scores, per-criterion results, judge reasoning, time, token usage and cost, saves everything to `evaluation_results.json` and plots `score_chart.png`.

## Key findings
Four of five cases (standard rejection, emotional applicant, protected attributes, Dutch B1) scored 5/5 on all judge runs and passed all rule checks; the average score was 4.4. The most important result is P3 (missing reason): the generated letter behaved correctly and did not invent a reason, and the rule-based fabrication check passed. The judge's own reasoning confirmed this, but it still marked `accurate_reason` as false and capped the score at 2. The cause was an ambiguity in my judge prompt: the task description says the letter must state the actual reason, while criterion 1 says not to invent one when none is given. The judge also missed two real issues in that letter: it implied the applicant's file was incomplete, and it contained unfilled placeholders. Rules and judge agreed on 4/5 cases; the one disagreement was exactly this edge case, which supports flagging disagreements for human review instead of trusting either method alone.

## Metrics and limitations
The full run (5 letters, 15 judge calls) took 67 seconds, used 22,024 tokens and cost $0.0049, roughly $4.73 per 10,000 letters (generation plus one judge run). Judge scores had zero variance across three runs at temperature 0, so repeated runs added little information. Limitations: five test cases is far too few for statistical conclusions; the same model generated and judged the letters, which risks self-preference and may explain the high scores; the rule-based checks are keyword-based and can miss paraphrases; and the Dutch B1 readability of P5 was not assessed by a human. Next steps: fix the judge prompt for "no reason given" cases, add a placeholder check, use a different or stronger judge model, and add human review on a sample.
